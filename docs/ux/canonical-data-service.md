# One authoritative catalog

The user requested no separate local catalog files and no outage fallback.

`atlas.catalog_read_model` applies the cleanup decisions without erasing original
research. The API additionally requires a current review with a retain/correct
disposition. Both the map and company list use that same projection. The map gets
catalog, graph, separately reviewed presentation copy and public-eligible media in
one SQL statement. A content revision identifies the result. Object type holds still
exclude incorrect graph cards and their touching edges; evidence remains preserved.
Company collections remain navigation, not validated problem taxonomy. The same
stable graph identities and evidence rules apply across every persona and zoom level.

Clients fetch without a saved-data fallback. Failure means an unavailable screen,
not a misleading empty catalog or an older release. A missing review keeps an entry
out of the projection. Funding pages use the same visibility rules. Media must retain
its provenance and public eligibility; unknown reuse rights are not silently promoted.

The website bundle contains code and illustrative artwork, not research snapshots.
Synthetic fixtures test rendering without distributing real catalog copies. Historical
commits remain recoverable history and are not a runtime data source.

## Research operations

The local research worker currently still uses its original SQLite stores and captured
source history. Removing website files does not migrate those operational stores.
Their cloud migration must preserve queue state, exact evidence versions, model traces,
held budget reservations and inspection history. Do not delete that history before a
verified migration. A dashboard must read the execution authority and distinguish
running, waiting, blocked, reviewed draft and delivered results.
